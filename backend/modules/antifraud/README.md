# 反诈风险线索（Issue #3，Draft 等待人工视频验收）

`GET /api/link-jobs/{job_id}/antifraud` 从已取得的转写、画面文字、抽样关键帧生成带时间点的规则与引流线索，查询机构公开证据，并使用项目已配置的模型做上下文综合判断。二维码通过 OpenCV 实际解码；相同二维码重复出镜只保留一次。模型输出必须引用输入中已有的证据 ID；模型未配置、失败、超时或返回无效证据时，保留规则线索并明确标为未完成模型判断。

报告不依赖未合并的 factcheck 分支。逐条说法遵循 #2 约定的 `claim/original_text`、`timestamp/evidence`、`verdict/risk`、`reason/sources/status` 字段。规则匹配或模型判断均不等于权威核实，条目保持 `unverified`。联系方式或二维码本身不被认定为诈骗；前端分别展示规则评分、模型可用时的综合风险以及机构来源。

## 机构公开证据核查

从文字中提取带时间点的机构全称（公司、银行、医院、研究院等后缀），复用现有 `web.search` / `web.fetch` 查询和读取公开来源。读取保留原有公网地址与每次重定向检查，不带浏览器登录凭证。全局 `LLM_WEB=off` 时不查询外部网页并明确显示未核实。

每个机构区分以下结果：

- `record_found`：读取到 `gsxt.gov.cn` 的页面正文，机构全称精确匹配唯一的企业/机构名称标签，同时有统一社会信用代码/注册号和登记状态。只表示找到这条公开登记记录；**注销/吊销等状态原样显示**，不代表当前经营正常，也不证明视频运营者与机构关联、持牌或产品安全。
- `official_reference`：取得官方 `.gov.cn` 页面正文对该机构的提及，但没有上述登记记录；保持登记与资质未确认。
- `unverified`：没有足够证据、只有第三方提及、联网关闭等；**无搜索结果不等于不存在机构**。
- `error`：检索/页面读取失败或超时，仍为未核实。

正文不包含机构全称的页面、搜索标题/摘要、第三方目录和仿冒官方域名均不能确立登记记录。多机构列表的名称/代码字段不互相拼接。来源链接与摘录随报告返回，便于人核验。机构证据缺失时报告为 `partial`。

可在项目既有配置中设置：

- `ANTIFRAUD_INSTITUTION_SOURCES=/path/to/sources.json`：机构全称到公开URL列表的 JSON，例如 `{"示例科技有限公司": ["https://www.gsxt.gov.cn/公开记录地址"]}`。此时优先直接读取指定页面，适合已有公开记录链接的情况；只设置URL不构成核实。
- `ANTIFRAUD_MAX_INSTITUTIONS=3`：本轮最多查几个机构，范围 1–5；超出的数量会明确显示未查。
- `ANTIFRAUD_INSTITUTION_TIMEOUT=20`：每个机构的查询与读取总超时秒数，范围 1–60，同时最多两个查询。每个机构最多读两页。

## 验收边界

- 工商登记查询门户可能要求验证码或登录，当前路径不绕过这些限制；无法读到正文/登记字段时保持未核实。没有使用付费注册库或上传任何凭证。
- 自然语言全称提取和严格登记字段识别都有覆盖限制，未命中不证明安全。取得登记记录也不代替金融/医疗资格核验或视频主体身份核验。
- 未运行真实付费模型的端到端效果评测；模型集成以可控测试客户端验证上下文、证据约束、超时与降级。
- 尚未以 5–10 条真实公开反诈视频做冒烟验收。
- 尚无人收集并确认诈骗类/正常类各几十条视频与标签，因此未测量 85% 识别率、10% 误报率，不声称达到这两个指标。
- 二维码只覆盖已采样的最多 64 帧；检测不到不等于完整视频没有二维码。

合并前应完成人工视频验收，并按实际数据确认机构名称提取和官方登记页面适配。不要把反诈宣传片中引用的诈骗话术当成宣传诈骗。
