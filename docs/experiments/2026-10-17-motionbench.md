# MotionBench 对比实验记录（2026-10-16 夜 — 10-17）

目标：检验"让 agent 长出视频理解能力"的几种做法，在细粒度动作理解上是否真的有效。

## 方法

- **数据**：MotionBench（Hong et al., CVPR 2025；Hugging Face `zai-org/MotionBench`，CC-BY-NC-SA-4.0，仅限学术研究）开发集，有标准答案的 4018 道单选题，6 个题型。
- **测试集**：每个题型随机抽 100 道（seed 0），共 600 道，所有配置用同一批题。**训练集**（积累经验、检验仪器）从其余题目中另抽，和测试集零重叠（代码里强制排除）。
- **模型**：DeepSeek（deepseek-flash），不联网、不带对话历史；要求必须选出一项（标准做法：弃权按答错计）。
- **统计**：同一批题上的配对 McNemar 检验（看"一方对、另一方错"的题），比较多组时要更严格。
- **脚本**：`backend/scripts/bench.py`（运行与报告），`backend/scripts/experience.py`（提炼经验）。

配置：

| 配置 | 说明 |
| --- | --- |
| A | 16 张均匀抽帧，不给工具 |
| A48 | 48 张均匀抽帧，不给工具（对照：只是多看帧有没有用） |
| B | 16 帧 + agent 工具（补看 `view_frames`、慢放复看 `replay`） |
| C | B + 感知仪器 `measure_motion`（镜头运动估计、运动强度曲线与峰值、周期、运动区域、热力图、轨迹叠影） |
| D | C + 从训练集提炼的经验库（第一轮 36 条，`data/bench/experience-r1.json`） |

## 结果

### 600 题（每类 100）

| 题型 | A48 | B | C | D |
| --- | --- | --- | --- | --- |
| 动作顺序 | 46.0% | **51.0%** | 49.0% | 42.0% |
| 镜头运动 | 55.0% | 58.0% | 62.0% | **64.0%** |
| 位置相关的动作 | 64.0% | 68.0% | 68.0% | **69.0%** |
| 动作识别 | 65.0% | 66.0% | **71.0%** | **71.0%** |
| 动作相关的物体 | 75.0% | 72.0% | **77.0%** | 74.0% |
| 重复计数 | 31.0% | 36.0% | 48.0% | **57.0%** |
| **全部** | 56.0% | 58.5% | 62.5% | **62.8%** |
| 平均输入 token | 10.7k | 11.3k | 12.2k | 23.3k |
| 调用了工具的比例 | 0% | 63% | 70% | 83% |

- C 在充值后重跑（带校准的仪器读数，见下文），**重复一次得 63.0%**：两次总分只差 0.5 个百分点，但有 109 道题（18%）两次结果不同——单题随机性很大，总分稳定。
- 配对检验（全部 600 题）：A48 vs C p = 0.002、A48 vs D p = 0.001（做了 6 组比较，Bonferroni 校正后门槛 0.0083，**仍然显著**）；B vs C p = 0.047、B vs D p = 0.033（未校正显著，校正后不显著）；C vs D p = 0.93。
- **重复计数**（每类 100 题）：A48 31% → C 48%（p = 0.0095）→ D 57%（A48 vs D：只有 A48 对 7 题，只有 D 对 33 题，p < 0.0001）。C vs D p = 0.12。计数题上 C 有 88/100、D 有 97/100 调用了仪器。
- 其他题型的差异都不显著（每类 100 题，配对检验 p > 0.1）。D 在动作顺序上比 C 低 7 个百分点（p = 0.21，不显著），值得关注。
- 第一次 C 运行（余额不足中断）已作废，移到 `data/bench/results/invalid/`。

### 204 题（每类 34，较早一轮）

A 52.9% · A48 52.0% · B 58.3% · C 59.3%。A vs A48 p = 0.88；A vs B p = 0.18；B vs C p = 0.88。
小样本里看起来的题型差异（比如重复计数 A 23.5% → B 44.1%，镜头运动 B 50% → C 58.8%）在 600 题上大多没有复现（重复计数 31% → 36%），**主要是随机波动**。每类只有 34 题时，单个题型要差 15 个百分点以上才可信。

## 不调用模型的仪器检验（训练集，不碰测试题）

API 停掉后，直接检验仪器读数本身对不对：

- **镜头运动**：41 道能归类的训练题里，仪器读数和正确答案一致 22 道（**54%**）；只凭仪器选答案选对 18 道（44%）。模型自己在镜头运动题上约 55–58%。→ **这个仪器不比模型准**，加给它主要是噪声。向上倾斜几乎测不出，推近常被误判成平移。
- **重复计数**：57 道训练题里，用"峰值数 ÷ 2"选最接近的选项，选对 **53%**；直接用峰值数 18%；用周期换算 16%；随机猜 25%。而模型在计数题上只有 31–36%（600 题）。→ **仪器信息比模型的判断更准，但模型没用好**：工具说明里写了"一个来回可能产生两个峰"，模型并没有据此换算。

## 带校准的仪器和经验库（C、D 用的版本）

- **带校准的仪器**：`measure_motion` 的每条读数后面附上它在训练题上测出的可靠度——镜头运动"和标准答案一致约 54%，推近常被误判成平移，只作参考"；计数直接给出"约 N 次（峰值数的一半）"，并注明"用这个估计选最接近的选项能选对 53%，直接用峰值数 18%，随机猜约 25%"。数字来自上面的训练集检验，写在 `modules/frames/instruments.py` 的 `CALIBRATION` 里。
- **经验库（第一轮）**：C 在 180 道训练题（每类 30，seed 7）上答题并记录完整取证过程（调用的工具、参数、读数、选择、对错），按题型交给模型复盘，提炼出 36 条可执行的经验（`data/bench/experience-r1.json`，`scripts/experience.py`）。D = C + 把全部经验放进系统提示（`EXPERIENCE_FILE`）。训练题 C 的正确率 59.4%。

## 第二轮：按类调取经验、第二轮经验（2026-10-17 上午）

- **D2**：答题前先让模型判断问题属于哪两类（训练题上前两类命中 94%，关键词规则只有 68%），只放这两类的经验（12 条，原来 36 条）。
- **D3**：用 D2 在 180 道新训练题（seed 13）上答题，结合第一轮的记录和经验，修订出第二轮经验（`data/bench/experience-r2.json`），按类调取。

| 题型 | C | D（全部经验） | D2（相关两类） | D3（第二轮） |
| --- | --- | --- | --- | --- |
| 动作顺序 | 49% | 42% | 43% | 48% |
| 镜头运动 | 62% | 64% | 67% | 61% |
| 位置相关的动作 | 68% | 69% | 65% | 60% |
| 动作识别 | 71% | 71% | 67% | 66% |
| 动作相关的物体 | 77% | 74% | 72% | 73% |
| 重复计数 | 48% | 57% | 51% | **60%** |
| **全部** | 62.5% | 62.8% | 60.8% | 61.3% |
| 平均输入 token | 12.2k | 23.3k | 19.4k | 19.9k |

- 计数：C vs D3 只有 C 对 7 题、只有 D3 对 19 题，p = 0.029。A48 → C → D3：31% → 48% → 60%。
- 整体：C、D、D2、D3 两两之间都不显著（p 0.26–0.93），都在 C 重复运行的噪声范围内。位置类 C vs D3：只有 C 对 14 题、只有 D3 对 6 题（p = 0.12）。
- token 没有降到 C 的水平：经验少了，但模型调用工具更多（C 70% → D3 86%）。
- **误伤的具体例子**：问"她举起猕猴桃片之后做了什么"，C 复看后答对（移到右眼前）；D3 去看视频结尾、答"放进碗里"——第一轮经验里有"问最终位置时必须看视频最后 1–2 秒"，这条被用到了不该用的地方。另一例中经验让模型对选项过度较真，放弃了正确答案。

## 结论

1. **只多给帧没用**（16 → 48 帧，0 提升，token ×2.7）。和 MotionSight"模型会平均掉帧间变化"的观察一致。
2. **主动取证（补看、复看）单独看提升不显著**（B vs A48 +2.5，p = 0.22）。
3. **带校准的感知仪器显著有效**：C 比只多给帧的 A48 高 6.5 个百分点（p = 0.002），主要来自重复计数（31% → 48%），token 只多 14%。关键不在"测"本身，而在**把仪器的可靠度和换算方法一起告诉 agent**：计数仪器在训练题上本身就有 53%，模型以前不会用（31–36%）。
4. **经验库（第一轮）在计数上继续提升**（48% → 57%，A48 → D 共 +26 个百分点），但总分和 C 持平（62.8% vs 62.5%）：它在计数、镜头运动上有帮助，在动作顺序上可能有损（−7，不显著），而且 token 翻倍（经验全部放进系统提示）。
5. 支持的说法："让 agent 知道自己的仪器有多可信、该怎么换算"，能在不训练模型的情况下显著提升细粒度动作理解中的计数；经验积累在计数上持续有效（第二轮到 60%），但**整体没有提升**：有的经验会被用到不该用的地方。
6. 由此看，经验不能"总结出来就全用"，需要逐条检验：在验证题上比较有它和没它，只保留确实有帮助的（见下一步第 1 条）。

## 下一步（建议）

1. **逐条检验经验**：从训练集再分出一批验证题，对每条（或每组）经验做"有它 / 没它"的对比，只保留确实提升验证集正确率的，会误伤的删掉或改写得更具体（写明适用条件）。再在测试集上测一次。这是让"从经验里长能力"可靠的关键。
2. **自动校准**：仪器的可靠度改为在积累经验时自动重新测量，写进经验库。
3. **在应用里落地**：答错反馈 → 记录取证过程 → 定期提炼并检验 → 经验本页面（查看、修改、停用）。
4. 镜头运动仪器本身只有约 54% 准确，还有改进空间。
5. 成本参考：600 题一组 C 约 730 万输入 token，D 约 1400 万，D2/D3 约 1200 万。
